# ThreatScope

Proactive cyber threat intelligence platform. Give it a domain; it performs reconnaissance, scores the resulting attack surface with a machine learning model, explains the score, correlates findings against public CVE data, and generates a written security report.

Bachelor's thesis project, Astana IT University (2026).

---

## What it does

1. **Reconnaissance** — resolves the target, scans ports, grabs service banners, pulls DNS records, inspects HTTP security headers, checks SSL/TLS certificate state, and enumerates subdomains.
2. **Feature extraction** — converts the raw scan into 28 numeric features (open-port flags, header presence, certificate validity, finding counts by severity).
3. **Risk scoring** — an XGBoost classifier assigns one of four risk levels (Low / Medium / High / Critical), with SHAP values attributing the decision to individual features.
4. **Threat correlation** — parses detected technologies and versions, matches them against NVD CVE records, and maps findings onto MITRE ATT&CK techniques.
5. **Reporting** — an LLM (Llama 3.3 70B via Groq) turns the structured scan result into a readable report, prioritised findings, and candidate attack paths.

```

  app/
    main.py                    FastAPI entry point — /api/scans/start, /api/report
    scanner.py                 port scan, banners, DNS, HTTP metadata, SSL, subdomains

    feature_service.py         scan result -> 28-feature vector
    ml_service.py              model loading and inference
    ml_train.py                training script
    scoring_service.py         risk aggregation
    cve_service.py             NVD CVE lookup and version matching
    mitre_service.py           MITRE ATT&CK mapping
    ttp_service.py             tactic/technique enrichment
    attack_path_service.py     attack path construction
    graph_service.py           NetworkX attack graph
    llm_service.py             Groq / Llama 3.3 70B report generation
    recommendation_service.py  remediation recommendations
    waf_service.py             WAF detection
    models/risk_model.pkl      trained classifier
frontend/
  Src/Pages/                   Dashboard, NewScan, Analysis, Assets, Intelligence, Reports
  Src/Components/              risk score card, findings panel, network/web sections, history
  Src/Services/api.js          backend client
```

**Stack:** FastAPI · XGBoost · SHAP · scikit-learn · pandas · NumPy · NetworkX · dnspython · React + Vite

## The model

| | |
|---|---|
| Algorithm | XGBoost multiclass classifier |
| Features | 28 (see `FEATURE_NAMES` in `ml_train.py`) |
| Classes | Low, Medium, High, Critical |
| Hyperparameters | 200 estimators, max depth 6, learning rate 0.1, subsample 0.8, colsample 0.8 |
| Split | 80/20 stratified |
| Interpretability | SHAP feature attribution per prediction |

**On the training data — read this before judging the accuracy number.** The model is trained on a *synthetic* dataset of 2,400 examples (600 per class), generated by rules derived from CIS and NIST hardening guidance. No labelled corpus of real scanned hosts was available for the project. The reported accuracy therefore measures how well the model reproduces the rule system that generated its data, not how well it predicts real-world risk. It is a working demonstration of the pipeline, not a validated risk predictor.

Feature definitions are shared between `ml_train.py` and `feature_service.py`, so training and inference see identical representations.

**Next step:** label a set of real scanned hosts and retrain, then report accuracy against a held-out set of genuine targets.

## Running it

**Backend**

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
echo "GROQ_API_KEY=your_key_here" > .env
uvicorn app.main:app --reload
```

API at `http://localhost:8000`, interactive docs at `/docs`.

**Frontend**

```bash
cd frontend
npm install
npm run dev
```

**Retraining**

```bash
cd backend
python -m app.ml_train
```

Writes `app/models/risk_model.pkl`.

## API

| Method | Endpoint | Purpose |
|---|---|---|
| `POST` | `/api/scans/start` | Run a scan against a target; returns assets, findings, risk score, CVE and ATT&CK data |
| `POST` | `/api/report` | Generate an LLM-written report from a scan result |

---

## Scope and limitations

- Scanning touches live hosts. **Only run it against systems you own or have written permission to test.**
- The risk model is trained on synthetic data (see above).
- Subdomain discovery is capped at 20 results; port scanning covers the first 100 ports by default.
- LLM output is generated text and can be wrong. Treat reports as a starting point for an analyst, not as findings of fact.
- No authentication on the API; intended for local use.
